# Wisp Technical & Operational Lag Audit — 2026-08-24

Method: five parallel subsystem audits (core, transport/TUI, multi-agent, tools/security,
packaging/CI/docs) plus hands-on verification: full test suite run, ruff/mypy, git & disk
forensics, and first-hand re-verification of every headline P1 against source at HEAD
`6482a3e`. ~80 distinct findings; the highest-impact ones are listed below with evidence.
Headline P1s marked ✅ were independently re-verified by a second reader.

---

## Verdict

**Good bones, prototype-grade wiring.** The architecture is sound (event spine, stateless
core, pure-function renderer, TOCTOU-safe file jail, real budget admission gate), the suite
is green and fast (2,762 passed / ~75s / zero collection errors), and TODO/FIXME markers are
near zero. But the lag lives at the seams: **controls written but never wired**, contracts
with **multiple owners**, **three generations of transport architecture coexisting**, and
docs that mislead in both directions. ~30–40% of transport-layer LOC is uninvoked
scaffolding. None of the critical fixes need redesign — they are defaults, wiring, and
deletion.

## Critical (compound risks — fix first)

1. ✅ **Out of the box, nothing requires approval.**
   `config.py:515` defaults `permission_mode=FULL`; the settings-table default `AUTO_EDIT`
   (`config.py:95-100`) is never consulted. In FULL, ToolExecutor skips the gating branch
   entirely (`tool_executor.py:216-218`) and the policy allow-all fires (`policy_engine.py:196-201`).
   Fresh install runs `run_bash`, `git_push`, writes — zero prompts.
   *Fix:* default AUTO_EDIT; reconcile settings table.

2. ✅ **LAN-reachable server executes host commands with no human in the loop.**
   `server/main.py:141` binds `0.0.0.0` by default; no `WISP_API_KEY` ⇒ auth auto-disabled
   "dev mode" (`server/deps.py:42,53-54`). Exposed: `POST /api/bash` falls back to
   NoopSandbox direct host execution without Docker (`sandbox.py:228-248`),
   `/api/swarm/run` hardcodes `auto_approve=True` (`routes/swarm.py:57`), and the WS
   transport **auto-approves every tool when no client is connected**
   (`websocket.py:75-76`). Compound with #1: a LAN peer can run arbitrary shell.
   *Fix:* loopback default bind; fail startup without a key on non-loopback;
   deny-by-default approvals.

3. **Hook privilege-escalation bypass via bash.** Filesystem tools refuse to touch
   `.wisp/hooks/*` ("prevent privilege escalation", `_utils.py:218-225`), but `run_bash`
   has no such guard (`bash.py:27-103`) and hooks hot-reload before every call
   (`tool_executor.py:474-475`), executing `shell=True` with `env=dict(os.environ)`
   (`hook_types.py:259,332-340`). One approved `cat > .wisp/hooks/x.json` permanently
   bypasses approval for all later calls.
   *Fix:* enforce hook-dir guard inside dangerous-command checks; allowlist hook env
   (`WISP_TOOL_ARGS=json.dumps(...)` also leaks full file contents into env,
   `hook_types.py:266-267`).

4. **Credential environment exposure; written defenses are dead code.**
   `scrub_sensitive_env()` (`tools/_utils_env.py:36-42`) and `_SENSITIVE_ENV_KEYS`
   (`_utils.py:226-244`) have **zero callers**; agent-spawned bash inherits all API keys
   (`bash.py:51-57`). DockerSandbox is wired only to the HTTP route, never to the agent loop.
   *Fix:* wire the scrubber into bash + hook subprocesses; wire sandbox or document host-trust.

5. ✅ **Subagent power envelope unenforced; recursion unbounded.**
   `_get_tool_schemas()` returns ALL schemas to every agent — `contract.tools`/role
   allow-lists exist only as prompt text (`stateless.py:884-898`,
   `subagent_orchestrator.py:1018-1021`). Subagents receive `spawn`/`fanout`, and each new
   contract resets `_subagent_depth=0` (`task.py:143` via `tool_executor.py:798`), so the
   depth check (`subagent_orchestrator.py:571`) can never trip — recursion bounded only by
   token budget. Guard functions (`spawn_with_guards`, timeout clamp, branching limit,
   local-model pick) exist with **zero callers** (`subagent_orchestrator.py:1198+,1384-1387`;
   live entry is `tool_executor.py:821→_run_with_retry`).
   *Fix:* filter schemas by contract; propagate depth; route spawn paths through guards.

6. ✅ **System-prompt cache collision poisons parent/subagent prompts.**
   `_SYSTEM_PROMPT_CACHE` keyed `(workspace, mtime)` only (`stateless.py:66-67`) while
   subagent task prompts are baked into the cached value as `role_extra`
   (`stateless.py:554-568,582`); delegation runs before `core.turn()` (`runtime.py:165-217`)
   and parallel subagents race one slot (max_concurrent=3).
   *Fix:* hash `role_extra` into the key.

7. **Provider failures masquerade as clean turn ends.** All three sync→async bridges push
   the `done` sentinel before the producer raises (`protocol.py:82-84`, `ollama.py:130-132`,
   `stateless.py:430-432`) — the exception dies in the thread excepthook. Corroborated
   empirically: unhandled `RuntimeError: Event loop is closed` from `stateless.py:429-431`
   escapes during ordinary test runs. Related: transient-retry classifier matches
   `"timeout"` but requests says `"Read timed out"` (`stateless.py:291-307`), and stream
   failures double-emit partial content into output *and* persisted history
   (`stateless.py:286-289 vs 309-311`).
   *Fix:* propagate exceptions through the queue; match `"timed out"`; emit accumulated
   content only if nothing streamed.

8. **Persisted tool-call history is invalid for OpenAI/NVIDIA.** Runtime persists dict args
   (`runtime.py:261-277`) while providers require JSON strings (`openai.py:283-294`); ids
   mismatch three ways (Ollama emits none `ollama.py:201-208`; core/runtime mint fresh
   `call_<uuid>`; results carry empty/missing `tool_call_id` — `stateless.py:360,371-374`,
   `runtime.py:271,289`, blocked paths omit ids `tool_executor.py:192-236`). First turn
   after any tool use gets a 400.
   *Fix:* stringify once at emission; one id minted at emission and threaded through.

9. **ACP sessions bypass every guard.** `ACPSession.execute_tool` calls
   `execute_tool()` directly — no ApprovalGate, no ToolExecutor, no dangerous-command check
   (`acp_session.py:207-213`).
   *Fix:* route through ToolExecutor like other transports.

10. **MCP integration broken + exploitable.** Three incompatible naming conventions
    (`mcp__srv__tool` at `extensions/mcp.py:67` vs dispatch `mcp:` prefix
    `tool_executor.py:707-716` vs manager `mcp:srv/tool` `mcp/manager.py:693`) ⇒ advertised
    tools always "Unknown tool". Conversely bare-named MCP tools win dispatch before
    builtins yet skip forced approval because `_needs_forced_approval` only tests the
    string prefix (`tool_executor.py:543,570`).
    *Fix:* one canonical naming; derive forced approval from `_is_mcp_tool()`.

11. **DAG scheduler runs dependents of failed nodes; threads zero data.**
    Level loop never inspects results (`dag.py:190-210`, ✅ verified); executor receives
    only the node — dependency outputs never injected (`subagent_orchestrator.py:927-948`).
    Zero tests. DAG-declared resource budgets are built then **never read** — runner builds
    fresh `ResourceBudget()` ignoring `metadata["_budget"]`
    (`subagent_orchestrator.py:933-941` vs `_runner.py:416-423,577-584`).
    *Fix:* skip descendants of failed nodes; inject dep results; honor metadata budget.

12. **Worktree/branch leak on crash — confirmed in code and on disk.**
    Cleanup sits ~10 awaits after creation with no try/finally
    (`subagent_orchestrator.py:655` vs `710-738`); no startup reaper. Empirical: 42 orphan
    dirs / 25 branches / 1.7 GB accumulated May–Aug; ~16 dirs fully unregistered.
    *(Cleaned 2026-08-24: `.wisp` 1.7 GB → 5.5 MB; salvage archive in /tmp.)*
    *Fix:* try/finally around run/cleanup; orchestrator-init sweep; user-facing GC command.

13. **Web tools leak/inject.** `web_fetch`: no SSRF guard (127.0.0.1/169.254.169.254/RFC1918
    allowed), redirects unvalidated (`web.py:209-232`), third-party proxy exfil by default
    (`r.jina.ai`, `web.py:36,165-169`). `web_search` HTML fallback disables TLS verification
    outright (`ctx.verify_mode=CERT_NONE`, `web.py:393-395`).
    *Fix:* resolve+block private IPs pre-request and per hop; proxy opt-in; default SSL context.

14. **Policy tiers target nonexistent tools.** Block lists name `"spawn_subagent"`
    (`security.py:49,55`, `policy_engine.py:256,261`) but registered tools are
    `spawn`/`fanout` (`registry.py:213,237`) — ASK_ALL/AUTO_EDIT denials never fire for
    subagents at the policy layer. ✅ verified.
    *Fix:* rename or derive from shared constant.

15. **Store silently shares state machine-wide.** On open failure, DB becomes predictable
    `/tmp/wisp_fallback.db` (`store.py:50-60`) merging full transcripts across workspaces
    and potentially users. Also: `save_run` delete+reinsert outside `transaction()`
    (`store.py:380-386`), `stop()` closes one thread's connection, ad-hoc ALTER migrations
    with no `user_version`.

## Remaining technical lag (P2/P3, by layer)

### Core engine
- Compaction slices mid-tool-pair (strict providers reject next call) and duplicates system
  messages; LLM summarize has **no timeout** and runs outside the turn timeout
  (`runtime.py:520-545`, `compaction.py:125-147`).
- Session-lock leaks: LRU eviction can evict a held lock (>1000 sessions); early generator
  close orphans `delegate_task` (children burn budget forever); `/compact` runs outside the
  session lock and mutates a copy (`runtime.py:118-122,171-188,563-576`, `commands.py:358-365`).
- Blocking I/O on the event loop every turn: prompt assembly stats/reads files, `os.walk`,
  git context, repo map (`stateless.py:501-593,702-718,831-844`) while tools carefully use
  `asyncio.to_thread`.
- Mid-stream stalls unguarded after first token (hang until 1800 s turn timeout);
  retry re-emits duplicate tool_call events (`stateless.py:1122-1138`).
- Trust auto-trusts any dir containing `.wisp/` — attacker-controlled in cloned repos
  (`trust.py:39-40`).
- P3: "stateless" core holds module-level caches growing unbounded; lazy `_approval_gate`;
  per-core circuit breakers don't share counts; self-mutating frozen `WispConfig` (~40
  config.json re-reads per construction); env-var schema drift (`WISP_CB_*` shorthand dead);
  ~12 resolved keys missing from SETTINGS_SCHEMA; quadruplicated dead `if name=="nvidia"`
  blocks in `factory.py:109-134` (default model missing `nvidia/` prefix);
  event-sourced replay drops TOOL_CALL events (`session.py:84-117`); dead `/tmp`-hardcoded
  background-run API; telemetry reads never-assigned `_model`; `__getattr__` infinite
  recursion risk in ollama provider during unpickling.

### Multi-agent
- Concurrent siblings overwrite each other's `share_finding` registration on the shared
  ExtensionHost (last registrant wins; never unregistered) (`_runner.py:364-373`).
- Failures/timeouts negatively cached and replayed as successes — even firing
  `subagent_complete` hooks; defeats the ×1.5 timeout retry introduced in the same class
  (`subagent_orchestrator.py:700-701,618-623,174`).
- `run_parallel_streaming` leaks abandoned children when consumer stops early — no finally/
  cancel (`subagent_orchestrator.py:832-844`).
- Vote tie-breaker decided by substring `"A"` (`"B, because it's pArallel…"` counts for A),
  checked before B (`_patterns.py:222-230`).
- Chain patches captured then destroyed without ever being applied — no consumer of
  `worktree_patch` (`_patterns.py:358-366,398`).
- Worktree create copies ALL parent-untracked files into each child (O(N²) growth in user
  repos lacking Wisp-specific ignores; silent `git apply` failure ignored)
  (`_worktree_manager.py:84-116,99`).
- Schema validator: `isinstance(True,int)` passes booleans as numbers; unknown declared
  types validate as True; unanchored regex; unbounded recursion escaping "never raises"
  (`schema_validator.py:111,117,143-155`).
- `wisp swarm` CLI is a single-agent stub; Ctrl-C calls nonexistent `stop_all()`;
  `agents status` crashes after any swarm run (`multi_agent/cli.py:86-87,104,128`);
  phantom import of nonexistent `.orchestrator` (`cli.py:17-20`).
- Contradictory retry policies (run() retries timeouts ×1.5; `_run_with_retry` documents
  and enforces no-retry); timed-out attempt's tokens never reach bookkeeping.

### Transport / UX
- **TUI↔server protocol mismatch end-to-end**: client expects `token`/`tool_approval_request`;
  server streams raw engine dicts typed `content`/`thinking` and emits `approval_request`
  (`tui/data/ws_client.py:114-143` vs `websocket.py:158-159,84-87`). Assistant text never
  renders; y/n/a/d keys dead. `wisp tui` production path passes NO transport — local
  approvals are no-ops (`__main__.py:47-61`, `workspace.py:222-259`).
- `CLITransport.send()` drops all events (no `_stdout` ever assigned), `recv()` always None —
  ABC methods non-functional; REPL bypasses them (`cli.py:519-520,548-569`).
- Spinner garbles MINIMAL mode (frames write `\r label` with no newline; succeed/fail
  early-return); truncation uses `len()` not `display_width()` → wide-char wrap
  (`spinner.py:42,70-79,111-128`).
- Mode-awareness bypassed ~15×: hardcoded ⚠️⏹🔮📋✗➜💉 etc. in cli.py/entry.py
  (e.g. `cli.py:613,648,762,1040-1061`; `entry.py:132,176,190,195,286-288`);
  icon branch keyed on always-true `display_width("✓")==1` making `[OK]` unreachable
  (`cli.py:1109-1114`); `_box()` pads by char count not display width → CJK border drift
  (`renderer.py:238,241`). Contradicts README:278's accessibility claim.
- `server.py:_redact_sensitive_tool_args` has zero production callers — tool args
  (file contents) stream raw to any WS client (`server.py:32-56,109-114`).
- WarpTransport dead/unintegrated: no callers, handles event types that don't exist,
  ships its own main() (`warp.py:250-304,348-430`).
- Exception path flushes buffers but never stops the spinner → daemon thread \r-overwrites
  the traceback (`entry.py:250-257` vs `cli.py:1001-1009`).
- Approval races: server denies-on-timeout without checking late approval; WS resolver

  `websocket.py:79-80`).
- SIGINT at idle prompt requires two Ctrl+C; `_transport_instances` grows unboundedly

- Dead-but-tested scaffolding: `protocol.Event`, both adapter classes, standalone

## Cross-cutting root causes

A. **Written-but-unwired controls** (the dominant pattern, ≥12 instances):
scrub_sensitive_env, _SENSITIVE_ENV_KEYS, DockerSandbox(agent-side), AuditLog.log_blocked,
_redact_sensitive_tool_args, spawn_with_guards/timeout-clamp/local-model-pick,
DAG metadata["_budget"], execute_tool(security_policy=...) param, ToolRegistry.execute
(no security/truncation), settings-table AUTO_EDIT default, event-replay TOOL_CALL case,
chain patch apply.
B. **Contracts with multiple owners**: tool-call serialization (core/runtime/providers),
MCP naming ×3, WS protocol ×2, permission defaults ×2, retry policy ×2, max command
length ×3 (schema 4096 / code 16384 / route 4096).
C. **Architecture generations coexist** without burial: legacy CLITransport ABC methods vs
REPL bypass; WarpTransport; ACP; server/websocket/TUI-vs-TUI-vs-TUI.
D. **Zero debt markers ≠ zero debt**: grep finds ~2 real TODOs; every landmine above is
unmarked. Marker hygiene created false confidence.
E. **Defaults lost arguments with docs**: FULL vs AUTO_EDIT is the clearest example — the
safe default exists in the schema and loses at resolution time.

## What's genuinely solid

Full suite green & fast with clean collection; mypy-strict spine passing; filesystem jail
with O_NOFOLLOW TOCTOU-safe fd I/O and realpath prefix checks; pure-function renderer core +

headroom floor; clean event taxonomy; tidy engine.py shim; conflicted patch-apply reverts
cleanly; worktree_isolated default consistent everywhere (False).
