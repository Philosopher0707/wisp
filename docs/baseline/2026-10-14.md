# Baseline, 2026-10-14: what `wisp` does, with proof

After M0 removed every front end but the CLI and the REPL. Every claim below is a test that
runs the real command (`python -m wisp`, under a pty for the REPL) against a scripted local
model, `tests/baseline/_model.py`. No fake core and no injected executor. CI runs these tests on
every change, so this page stays true or a test goes red.

Run them yourself (about 15 s):

```bash
python -m pytest -q tests/baseline -rxX
```

## What works

| # | Claim | Proof |
|---|---|---|
| B1 | `wisp --help` lists the CLI commands (`run`, `repl`, `session`, `swarm`, `graph`, ...) and not `server`, `tui` or `acp`. Those three now exit 2 with a pointer | `test_b1_…`, `tests/test_removed_subcommands_refuse.py` |
| B2 | A coding task, end to end: the model reads a file, edits it, runs the tests and answers. The edit is on disk, and the project's own test passes when run independently. A verified turn is not called unverified | `test_b2_…` |
| B3 | A turn that changes code and claims success without running anything gets a harness-written note: "the completion claim above is not backed by any verification". The model cannot remove it | `test_b3_an_unverified_change_…` |
| B4 | `rm -rf important` is refused before it runs, even under `--print`'s `full` permission mode. The files survive | `test_b4_…` |
| B5 | In `auto_edit`, the REPL asks before a write. `n` leaves the file absent; `y` writes it | `test_b5_the_repl_asks_…` (both answers) |
| B6 | `-S <id>` continues a stored session: the model is sent the earlier exchange | `test_b6_a_named_session_…` |
| B7 | By default the parent model is offered the 11 core tools and **not** `spawn` or `fanout`. The model cannot delegate unless `WISP_TOOL_PROFILE=full`; people can, with `/spawn` and `/swarm` | `test_b7_…` |
| B8 | With `WISP_TOOL_PROFILE=full`, a model's `spawn` runs a child that does the work. The parent's tool result carries the evidence (`files`, a `file` evidence item, the test state), and the child has an agent record | `test_b8_…` |

Test suite at this baseline (local, macOS, Python 3.12): **11,824 passed, 1 failed, 6 skipped,
2 xfailed** in 19 min, plus the 9 baseline tests and 4 known-defect pins below. The one failure is
`test_preflight_doctor::…no_runner_fails`, which needs the Docker daemon; Docker was not running
on this machine. CI on Linux is the reference.

## Known defects (pinned, not fixed)

Each is a strict `xfail` with the correct behaviour as its assertion. Fixing the defect makes
the test pass, and a strict xfail that passes fails the suite, so this list cannot go stale
silently. Each was confirmed with `--runxfail` to fail for exactly the stated reason.

| # | Defect | Measured | Pin |
|---|---|---|---|
| D1 | A withheld answer is kept: each round the harness rejects ("not backed by verification") leaves its draft in the final answer | "Done. All tests pass." appears 6 times in one answer | `test_b3_known_defect_…` |
| D2 | A refused write is reported as a change: after `n`, the REPL still says "this turn changed code … UNVERIFIED", sends verification nudges, and lists `Files: new.txt` for a file that does not exist | REPL transcript | `test_b5_known_defect_…` |
| D3 | Every `--print` run in a workspace joins one stored session named `headless`, so an unrelated one-shot prompt is sent the previous run's conversation | The second run's request contained the first run's prompt | `test_b6_known_defect_unrelated_…` |
| D4 | `--print` JSON reports `"iterations": 0` for a turn that made two model calls | `iterations` 0, 2 requests | `test_b6_known_defect_print_reports_…` |

Also measured, not yet pinned:
- **Two finish judges overlap.** On the path in B3, the reasoning core's R1 wrote the note, not `core/honest_finish`'s UNVERIFIED line; on the path in D2, honest_finish wrote it. Which one speaks depends on the path. Milestone M1 makes them one.
- **A capability report has no reader.** The `subagent_start` event's report was read only by the removed desktop app.

## Misconceptions removed in M0

| Was said | Is true |
|---|---|
| Wisp has a server, a TUI, a desktop app, Android, VS Code and Warp clients, an ACP adapter and a Docker deployment | It has the CLI and the REPL. The rest were removed, and can be restored from `checkpoint/2026-10-14/main-pre-m0-subtract` (`docs/removed/2026-10-14-m0-front-ends.md`) |
| `wisp -p` uses a local server when one is running | It always runs in-process |
| `wisp server` / `wisp tui` start a front end | They exit 2 with a pointer. Before the refusal, they were sent to the model as a prompt |
| A tag push builds a release with an APK and a Docker image | `release.yml` runs the suite and publishes notes. Before this, it installed without the dev extras on a shallow clone, so its test step could not have passed |
| `CLAUDE.md`, `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `QUICKSTART.md`, `ADMIN-GUIDE.md` describe the removed surfaces | Corrected |
